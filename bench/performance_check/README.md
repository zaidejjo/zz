# Performance / Stress / Memory Benchmark Suite — ZZ vs Go vs Rust

Three equivalent workloads, three implementations, one runner.

## Layout

```
bench/performance_check/
├── README.md
├── run.sh              # benchmark runner (timing, RSS, binary size, MD table)
├── zz/                 # ZZ source
│   ├── bench_memory_leak.zz
│   ├── bench_cpu_intensive.zz
│   └── bench_string_concats.zz
├── go/                 # Go reference implementation
│   └── main.go
├── rust/               # Rust reference implementation
│   ├── Cargo.toml
│   └── src/main.rs
├── RESULTS.md          # ← regenerated by run.sh
├── results.json        # ← regenerated by run.sh
├── .bin/               # compiled artifacts (gitignored)
└── .log/               # build/measurement logs (gitignored)
```

## Workloads

| Benchmark              | What it stresses                                       |
|------------------------|--------------------------------------------------------|
| `bench_memory_leak`    | 50M short-lived array+dict allocs across two passes    |
| `bench_cpu_intensive`  | 10M integer accum + 1M pow/mod + 1M array fill/sum    |
| `bench_string_concats` | 50×5000 + 20×2000 + 10000 string concatenations        |

## Metrics

- **elapsed_ms** — wall-clock best-of-N (default N=3, set `RUNS=5`)
- **peak_rss_kib** — peak RSS via `/usr/bin/time -v` (ps fallback on macOS)
- **binary_kib** — size of the compiled/executed artifact

## Run

```bash
cargo build --release   # produces target/release/zz
RUNS=5 bash bench/performance_check/run.sh
```

Outputs:

- `bench/performance_check/RESULTS.md` — human-readable Markdown table
- `bench/performance_check/results.json` — machine-readable

## Regression baselines

`crates/zz_cli/tests/performance_check_regression.rs` enforces:

- `bench_memory_leak` → peak RSS < **15 MB**
- `bench_cpu_intensive` → wall time < **60 s**
- `bench_string_concats` → peak RSS < **20 MB**

Tweak baselines in that file if the workload sizes change.
