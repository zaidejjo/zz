# TLS client transport (Track T, T-A)

> Decision: **T-A stdlib `net.tls_connect`** via `rustls` (ring, TLS 1.2/1.3).
> The toolchain already links `rustls` + `webpki-roots` in both
> `zz_stdlib` (VM, HTTP server TLS) and `zz_native_rt` (AOT staticlib,
> PG `require` TLS). A generic TLS client reuses that dependency with
> zero new system deps, keeps VM and native byte-identical (same Rust
> driver), and serves every package — not just redis-zz.
> Rejected T-B plugin: more moving parts (ABI, distribution) for no
> security benefit; a plugin can still wrap this driver later.

## Contract (what redis-zz codes against)

- `net.tls_connect(addr, server_name, timeout_ms)` — verify ON (webpki roots), SNI sent, hostname verified, TLS 1.2 min. Timeouts bound dial + handshake + IO.
- `net.tls_connect_with_ca(addr, server_name, ca_file, timeout_ms)` — same + extra PEM trust root (self-signed test certs).
- `net.tls_connect_insecure(addr, server_name, timeout_ms)` — explicit opt-in, verification OFF. Emits no silent downgrade: the name says insecure, and callers must surface one warning event (redis-zz metrics hook does).
- Same method set as TCP: `read / read_bytes / read_exact / read_line / write / write_bytes / set_read_timeout / set_write_timeout / shutdown / close`.
- Errors carry a reason class prefix so callers match without string-scraping internals: `tls:handshake_failed | tls:cert_untrusted | tls:cert_hostname | tls:refused_tls | tls:timeout | tls:io`.

## Verify (T2)

See `tests/fixtures/stdlib/net_tls_test.zz` (VM + native parity): handshake against a loopback rustls server with valid CA, self-signed without CA fails `cert_untrusted`, wrong hostname fails `cert_hostname`, plaintext-on-TLS-port fails `refused_tls` (no hang), `insecure` connects, timeout honored, 1 MB round-trip byte-equal.
