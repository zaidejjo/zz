# S3 — Realistic programs d1–d8 classification

"UE" = **Unintended Effect**: behavior that differs from programmer intent
due to a race condition or state-access-outside-atomic, even if the program
happens to produce the "expected" output in a single run. A UE is not
necessarily a checker diagnostic; it is a semantic correctness problem that
the program exhibits under contention.

## d4 fix

`d4_rate_limiter.zz` — `allow()` does:
```
if tokens > 0 {
    tokens = tokens - 1
    return true
}
```
outside `atomic {}`. Both the read (`tokens > 0`) and write (`tokens = ...`) must be inside one `atomic {}` block to be atomic. Fix:

```zz
func allow() -> bool {
    atomic {
        if tokens > 0 {
            tokens = tokens - 1
            return true
        }
        return false
    }
}
```

## d8 fix

`d8_config_reload.zz` — `reload()` does:
```
cfg = Config { timeout: timeout, retries: 3 }
```
outside `atomic {}`. Fix:

```zz
func reload(timeout: int) {
    atomic {
        cfg = Config { timeout: timeout, retries: 3 }
    }
}
```

## d6 note

`d6_log_buffer.zz` — `record()` now wraps the state log push in `atomic {}`
(fixed). Previously it wrote `state log` outside `atomic {}`, which was a UE
(concurrent pushes could interleave and lose updates). AOT gave `log_len=1`
instead of `4`, confirming the race. Now fixed and race-free.
