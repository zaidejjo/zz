# S2 — nolock_selftest code proof (VM + AOT)

This file proves that `nolock_selftest` disables ONLY the state lock
acquisition/release, NOT safepoints/yield scheduling, for BOTH VM and AOT,
covering BOTH atomic writers AND batched readers.

======================================================================
VM — crates/zz_runtime/src/vm/runtime.rs
======================================================================

1. state_lock_held() — batch depth excluded from lock-under-nolock
   Lines 232-247:
     fn state_lock_held(&self) -> bool {
         if self.state_lock_depth > 0 { return true; }
         #[cfg(not(feature = "nolock_selftest"))]
         {
             if self.state_batch_depth > 0 { return true; }
         }
         false
     }
   Under nolock_selftest, state_batch_depth > 0 does NOT count as holding
   the lock. Only atomic { } (state_lock_depth > 0) counts.

2. Op::Atomic — lock acquisition disabled under nolock
   Lines 1127-1138:
     Op::Atomic { body, span } => {
         // Under `nolock_selftest` the lock is disabled so atomic
         // bodies run lock-free (selftest only);
         if !cfg!(feature = "nolock_selftest") {
             let reg = ...;
             reg.acquire();
             self.state_lock_depth += 1;
         }
   Under nolock, the atomic writer does NOT acquire the state lock.
   Both writers (writer_fwd, writer_back) run lock-free.

3. leave_atomic() — lock release disabled under nolock
   Lines 555-562:
     // Under `nolock_selftest` the lock is disabled; `Op::Atomic` did not
     // acquire, so do not release here either (keep depth balanced).
     if !cfg!(feature = "nolock_selftest") {
         self.state_lock_depth -= 1;
         reg.release();
     }
   Under nolock, release is also skipped — depth stays balanced.

4. Op::LoadState — direct map access under nolock (no lock)
   Lines 1057-1070:
     let v = if cfg!(not(feature = "nolock_selftest"))
         && (self.state_lock_depth > 0 || self.state_batch_depth > 0)
     {
         unsafe { reg.map_mut().get(name).cloned() }
     } else {
         reg.get(name)   // locks per-access, releases immediately
     };
   Under nolock, the `cfg!(not(...))` condition is false, so it always
   takes the `else` branch: `reg.get(name)` which locks per-access and
   releases immediately — no lock held across reads.

5. Op::StoreState — same as LoadState
   Lines 1084-1098:
     if cfg!(not(feature = "nolock_selftest"))
         && (self.state_lock_depth > 0 || self.state_batch_depth > 0)
     {
         unsafe { reg.map_mut().insert(name.clone(), v); }
     } else {
         reg.set(name, v);
     }
   Under nolock, always uses `reg.set()` (lock-free per-access).

6. Op::StateBatchBegin — acquire skipped under nolock
   Lines 1171-1186:
     Op::StateBatchBegin(_span) => {
         // nolock_selftest: batch reads do NOT acquire the state lock
         #[cfg(not(feature = "nolock_selftest"))]
         if self.state_batch_depth == 0 { _reg.acquire(); }
         self.state_batch_depth += 1;
     }
   Under nolock, `reg.acquire()` is NOT called. Batch depth is tracked
   but no lock is acquired.

7. Op::StateBatchEnd — release skipped under nolock
   Lines 1187-1200:
     Op::StateBatchEnd(_span) => {
         self.state_batch_depth -= 1;
         // nolock_selftest: batch reads do NOT release the state lock.
         #[cfg(not(feature = "nolock_selftest"))]
         if self.state_batch_depth == 0 { reg.release(); }
     }
   Under nolock, `reg.release()` is NOT called.

CONCLUSION (VM): nolock_selftest disables lock acquire/release for BOTH
atomic writers (Op::Atomic) AND batched readers (StateBatchBegin/End,
LoadState/StoreState). Safepoints/yield scheduling are NOT affected
— they are controlled separately by needs_safepoint() in zz_lower
(see AOT section) and the VM's independent yield_check!() mechanism.

======================================================================
AOT — crates/zz_lower/src/context.rs
======================================================================

1. needs_state_lock() — returns false under nolock
   Lines 1091-1104:
     pub(crate) fn needs_state_lock(&self) -> bool {
         if cfg!(feature = "nolock_selftest") {
             return false;
         }
         self.needs_safepoint()
     }
   Under nolock, needs_state_lock() ALWAYS returns false. No zz_state_lock/
   zz_state_unlock calls are emitted for any state access.

2. needs_safepoint() — KEPT under nolock (scheduling still works)
   Lines 1066-1082:
     // nolock_selftest feature: keep cooperative safepoints on so task
     // scheduling still works, but disable the state lock itself via
     // needs_state_lock().
     if cfg!(feature = "nolock_selftest") {
         return self.has_extern_plugin
             || self.reachable_natives.iter().any(|n| n.contains("task")
                 || n.contains("chan") || n.contains("spawn"));
     }
   Under nolock, needs_safepoint() still returns true when task/chan/spawn
   is reachable — safepoints/yield scheduling are preserved.

3. emit_state_read() — uses needs_state_lock() to decide lock emission
   Lines 1106+: emit_state_read() calls needs_state_lock(); when false
   (nolock), no zz_state_lock/zz_state_unlock is emitted around batched
   state reads. Both writers (RMW) and readers (loads) run lock-free.

CONCLUSION (AOT): nolock_selftest disables the state lock entirely via
needs_state_lock() returning false, while needs_safepoint() remains
active for task/chan/spawn reachability. Both writers and readers run
lock-free.
